# MAP-38B Differential Control Test

MAP38B_DIFFERENTIAL_CONTROL_TEST_PACKET_DEFINED

This packet reworks MAP-37E's differential control test pattern for
`renderable_v1` (MAP-38A). It is generated (and can be regenerated) by
`scripts/prepare-build42-map38b-differential-control-test-packet.ps1`, which
invokes the real CLI writer (`map-export-experimental --build42-candidate-writer
--build42-candidate-profile renderable_v1`) rather than any hand-crafted
scaffolding.

## Why this test exists

MAP-38A found and fixed the reason no PZMapForge Build 42 candidate had ever
rendered distinctly (wrong folder structure, wrong `map.info` `lots=` value,
a flat zero-payload lotpack, and — the costliest mistake — test content
indistinguishable from Build 42's own procedural wilderness fallback). The
fix was confirmed in **one unrepeatable human runtime test** (2026-07-08).

MAP-37E already established, for the OLD chunkdata format, that a
single-run "spawn + visible terrain" test cannot distinguish authored
content from fallback wilderness — that differential test returned
`FALLBACK_INDISTINGUISHABLE`. This repo's own evidence-discipline rule ("a
passing test suite does not promote provisional behavior to canon")
applies just as much to a single passing *human* test. MAP-38B runs the
same wiring twice — once with the `renderable_v1` candidate files present,
once with them removed — and compares.

## What this tests

Whether the visibly artificial, grid-aligned vegetation pattern recorded in
the MAP-38A session (the `unofficial_fork_map_0` marker tile, lotheader
index 4) can be attributed to the renderable_v1-generated
`35_27.lotheader` / `world_35_27.lotpack` / `chunkdata_35_27.bin`, using:

- **Run A (files-present)** — a freshly-generated `renderable_v1` candidate,
  unmodified, under the MAP-38A folder fix
  (`common/media/maps/<mapId>/`, not `<version>/media/maps/<mapId>/`).
- **Run B (files-removed)** — an identical install with those three files
  deleted.

Both runs use identical mod metadata, identical map token, and identical
server wiring — the MAP-9K/9L/9Q proven mount shape, unchanged by MAP-38A:

    Mods=pzmapforge_map38b
    Map=pzmapforge_map38b
    SpawnPoint=10746,8288,0

Separately, inside the mod's own `map.info` (a different field from the
server ini `Map=` line above), MAP-38A's fix applies:

    lots=Muldraugh, KY

## Eight outcomes, narrowed for the MAP-38A content-choice lesson

Outcomes 1-6 (`MOD_NOT_LOADED`, `SPAWN_METADATA_FAIL`,
`MAP_FOLDER_REGISTRATION_FAIL`, `CHUNKDATA_PARSE_FAIL`,
`MULDRAUGH_FALLBACK`, `EMPTY_WORLD`) are evaluated per run. Outcomes 7 and
8 are evaluated only after both runs are complete:

- **Outcome 7 — `RENDERABLE_MOUNT_SUCCESS` (narrowed further than
  MAP-37E's `TERRAIN_MOUNT_SUCCESS`):** Run A shows the *specific*
  grid-aligned vegetation patch pattern AND Run B does not. "Run A terrain
  differs from Run B" is explicitly **not** sufficient by itself — MAP-38A's
  own record shows natural/blend ground tiles are format-correct, likely
  render, and are still visually indistinguishable from procedural
  fallback. Any difference that isn't the specific grid-regular pattern
  must be recorded as Outcome 8, not Outcome 7.
- **Outcome 8 — `FALLBACK_INDISTINGUISHABLE`:** Run A and Run B render
  similarly, or Run A's difference from Run B isn't the specific
  grid-aligned marker pattern. Meaning: the MAP-38A finding did not
  reproduce under this packet's staged candidate.
