# MAP-37E Differential Control Test

MAP37E_DIFFERENTIAL_CONTROL_TEST_PACKET_DEFINED

This packet reworks the MAP-37D human runtime load-test into a two-run
differential control test. It is generated (and can be regenerated) by
`scripts/prepare-build42-map37e-differential-control-test-packet.ps1`.

## Why MAP-37D's criterion was insufficient

MAP-37D's TERRAIN_MOUNT_SUCCESS criterion was "player spawns near the
expected coordinate and terrain is visible." That is exactly the signal
MAP-9L recorded once (MAP9L_GENERATED_PZMF_BINARY_TERRAIN_RENDERS_VISUALLY).
MAP-9N subsequently observed generic procedural/fallback wilderness
rendering even when the generated 35_27 cell files were removed entirely,
and MAP-9Q confirmed a structurally correct, known-good empty lotheader
still only produced indistinguishable fallback/procedural forest. A
single-run "spawn + visible terrain" test cannot tell authored content
from Build 42's fallback wilderness renderer. This packet closes that gap
by running the same wiring twice, once with the candidate binary files
present and once with them removed, and comparing the two.

## What this tests

Whether visible terrain at cell 35_27 can be attributed to the
PZMapForge-generated `chunkdata_35_27.bin` / `35_27.lotheader` /
`world_35_27.lotpack`, using:

- **Run A (files-present)** — the MAP-37C staged candidate, unmodified
  (1026-byte chunkdata, 00 01 header + 128 zero records; MAP-37B/C shape).
- **Run B (files-removed)** — an identical install with those three files
  deleted from the map folder.

Both runs use identical mod metadata, identical map token, and identical
server wiring — the MAP-9K/9L/9Q proven mount shape:

    Mods=pzmapforge_map37c
    Map=pzmapforge_map37c
    SpawnPoint=10746,8288,0

No `;Muldraugh, KY` chain. MAP-9D proved that shape (self-token +
Muldraugh chain) produces an empty IsoMetaGrid map-folder list across five
folder-layout variants; MAP-9K/9L/9Q proved the Muldraugh-free, direct
`SpawnPoint=` shape reaches a mounted, rendering state. MAP-37D reused the
MAP-9D shape by mistake — this packet corrects that.

## Eight outcomes

Outcomes 1-6 (MOD_NOT_LOADED, SPAWN_METADATA_FAIL,
MAP_FOLDER_REGISTRATION_FAIL, CHUNKDATA_PARSE_FAIL, MULDRAUGH_FALLBACK,
EMPTY_WORLD) are evaluated per run. Outcomes 7 and 8 are evaluated only
after both runs are complete, by comparing them:

- **Outcome 7 — TERRAIN_MOUNT_SUCCESS (narrowed):** Run A shows visible
  non-empty terrain AND Run B does not show the same terrain (empty,
  crashed, errored, or clearly distinguishable). "Run A spawned and showed
  visible terrain" alone is explicitly NOT sufficient — see
  `MAP_37E_SUCCESS_FAILURE_CRITERIA.md`.
- **Outcome 8 — FALLBACK_INDISTINGUISHABLE:** Run A and Run B both spawn
  successfully and render visually similar wilderness/terrain. This means
  visible terrain in Run A cannot be attributed to the authored
  PZMapForge files. Per MAP-9N/MAP-9Q precedent, this is the expected
  result. If this outcome applies, TERRAIN_MOUNT_SUCCESS must NOT be
  recorded.
